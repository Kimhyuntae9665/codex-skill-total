# Total

프로젝트·포트폴리오를 Council로 검토하고 네 스킬의 적용 지점을 찾아 실제 개선과 검증까지 수행한다. 의견 나열이나 계획 제시로 끝내지 않는다. 사용자에게는 한국어로 설명한다.

## 의존 스킬

원본을 실제로 읽고 실행한다. 이 스킬은 아래 다섯 스킬의 대체 구현이 아니다.

| 스킬 | 번들 진입점 | 담당 |
|---|---|---|
| Council | [SKILL.md](../council/SKILL.md) | 독립 검토·적용 지점 선택·방향 통합 |
| UI/UX Pro Max | [SKILL.md](../ui-ux-pro-max/SKILL.md) | 정보 구조·인터랙션·디자인 시스템 |
| Graphify | [SKILL.md](../graphify/SKILL.md) | 코드 구조·호출 관계·변경 영향 근거 |
| Impeccable | [SKILL.md](../impeccable/SKILL.md) | 화면 구현·가독성·사용성·시각적 마감 |
| Archify | [SKILL.md](../archify/SKILL.md) | 실제 근거에 맞는 대화형 구조도·업무 흐름도 |

경로가 바뀌었다면 사용자 홈의 `.agents/skills`, `$CODEX_HOME/skills` 또는 `.codex/skills`에서 동일한 이름을 찾는다. 원본을 복제하거나 다른 도구로 조용히 대체하지 않는다. [scripts/check_dependencies.py](scripts/check_dependencies.py)는 진입점·로컬 리소스·런타임 후보의 존재를 읽기 전용으로 확인한다. 결과는 실제 실행 성공이나 Council 모델 사용 가능성의 증거가 아니다.

## 1. 대상과 범위 확인

- 지정 경로·첨부·현재 프로젝트를 우선한다. 명확한 대상은 다시 묻지 않는다. 대상이 없거나 충돌하면 필요한 대상만 질문하고 임의 폴더에 개선을 적용하지 않는다.
- 기본은 요청 범위의 **개선 적용과 검증**이다. `검토만`, `코드 수정 없이`, `제안만`은 원본 수정 없는 분석이다. 기존 자료만·지정 디자인·페이지 수·출력 형식 등 사용자 제약을 보존한다.
- 현재 대상 프로젝트의 AGENTS.md와 [karpathy-guidelines](../karpathy-guidelines/SKILL.md)를 읽는다. 새 구현·포트폴리오 재구성에서는 [포트폴리오 제작 지침](references/portfolio-guidance.md)을 읽고, 독립 구현 위임이 허용되고 유용하면 [6-1-sol-orch](../6-1-sol-orch/SKILL.md)를 적용한다. 사용자가 보유한 추가 프로젝트·채용 지침은 해당 범위에서 우선 적용하되 이 배포본에 없는 개인 원장이나 특정 PC의 guidance 파일을 필수 의존성으로 삼지 않는다.
- 사용자 변경과 원본을 보존한다. 현재 화면·소스·핵심 조작·오류·빌드 방법을 조사해 최소 근거를 모은다. 조사 단계에서 원본을 개선하지 않는다. 기존 Graphify 그래프를 조회할 때도 현재 소스와의 일치·커버리지를 확인한다. 초기 추출이 필요하면 생성되는 분석 파일을 명시하고 별도 작업 폴더/복사본에서 원본·기존 그래프를 보존한다. `파일 생성도 금지`이면 조회만 한다.

## 2. Council 먼저 실행

Council 진입점과 [references/council-routing.md](references/council-routing.md)를 읽는다. 원문 요청을 보존하고 같은 근거 패킷으로 Council을 실제 실행한다.

- 현재 Council의 정확한 모델·max 프로필, **독립된 다섯 역할**, 제한된 재시도·마감, 유효한 terminal 결과 게이트를 따른다. 다섯 결과를 받기 전 통합하지 않는다.
- **다섯 결과 게이트 → 지정 Sol 통합 성공 → 루트의 원문·의견 충실도 검사 통과** 후 개선을 적용한다. 계획에 Council이라고 쓰거나 루트가 역할극을 하는 것은 실행이 아니다.
- 네 스킬 **모두의 적용 가능성**을 검토한다. 각 스킬을 적용 / 해당 없음 / 근거 부족 / 실행 불가로 표시하고 이유를 남긴다. 필요한 적용 지점을 생략하지 않으며 불필요한 실행·산출물도 강제하지 않는다.
- Council 실행 실패 시 단계와 이유를 알리고 이 통합 흐름의 개선 적용을 멈춘다. 독립적으로 허용된 진단은 계속할 수 있지만 부분 검토를 Full Council이라고 부르지 않는다.
- 실행 완료와 근거 신뢰도를 구분한다. 근거 부족 제안은 보류하거나 검증 가능한 범위로 좁힌다.

## 3. 개선 적용

채택된 개선마다 `대상 → 현재 문제·근거 → 담당 스킬 → 변경 → 확인할 결과`를 짧게 기록한다. 적용할 스킬의 진입점과 해당 참고문서를 실제로 읽고 사용한다. 도구별 고정 순서 대신 개선의 의존 관계를 따른다.

- **Graphify:** 구조 변경 전 호출·의존 관계와 영향 범위를 확인한다. 추출 관계·추론·모호한 관계를 구분하고 현재 소스와 대조한다. 그래프만으로 정상 동작을 판단하지 않는다.
- **UI/UX Pro Max:** 화면의 목적과 기존 정체성에 맞는 디자인·UX 규칙을 검색하고 적용한다. 일반 검색 fallback을 제품 적합성으로 받아들이지 않는다.
- **Impeccable:** 해당 화면·문제의 playbook으로 구현·개선한다. 프로젝트 cwd에서 context를 한 번 로드하고 UI 수정 직전 craft-floor를 읽는다. 정체성을 유지하는 개선과 요청된 재설계를 구분한다. 실행기 실패 시 원본이 명시한 문맥 직접 읽기 대체 경로를 따른다.
- **Archify:** 시스템·업무 이해에 필요한 경우 실제 소스·흐름 근거로 적합한 semantic type의 대화형 HTML을 만든다. 추정 관계를 실제 구조로 표시하지 않는다. 상태·결과 이해가 핵심 문제라면 Council 이후 근거 확인 → 흐름도 → 화면 수정 순서도 가능하다. 도식이 수정 위치·검증 기준을 구체화하지 못하면 추가하지 않는다.

Graphify는 분석 근거, Archify는 사람이 탐색할 설명을 만든다. UI/UX Pro Max는 설계 기준, Impeccable은 실제 화면·사용성 적용을 담당한다. 두 디자인 스킬은 같은 사용자 브리프와 디자인 방향을 공유한다.

하위 제작 오케스트레이션은 필요한 독립 구현에만 적용한다. 같은 결정에 Council을 중복 실행하거나 피어 의견을 선행 Council 역할에게 보내지 않는다. 도구 실패는 허용된 원본 대체 경로를 먼저 확인하고 영향 받는 개선을 blocked로 기록한다. 독립적인 채택 개선은 진행할 수 있지만 필수 개선 누락을 전체 완료로 표시하지 않는다. 이미 승인된 로컬 수정·실행·검증을 반복 승인받지 않는다. 게시·배포·발송·최종 제출·비용 발생은 현재 사용자 권한 범위를 따른다.

## 4. 검증하고 전달

[references/application-and-validation.md](references/application-and-validation.md)를 해당 결과 형식에 맞춰 읽는다.

- 변경 전후를 실제 화면·소스·핵심 조작으로 비교한다. 적절한 빌드·테스트와 실행 확인을 수행한다. UI는 실제 대상 기기·키보드·오류 상태를 확인한다.
- Impeccable의 검사·수정 상한을 전체 UI 마감에 적용한다. 합동 첫 검사 → 수정 한 번 → 확인 한 번을 기본으로 하고 반복 취향 변경 루프를 만들지 않는다.
- 포트폴리오는 최종 형식으로 렌더링·재열람한다. 적용 지침의 직무 연결 문장, 스크린샷 네 변 테두리, 시뮬레이션 관찰 안내·연결선, 페이지 제약과 사실 구분을 검수한다.
- 실패·미실행·미확인을 구분한다. 그래프 생성·정적 검사·자동 브라우저 검사·실제 육안 검사·기능 테스트를 서로의 증거로 대체하지 않는다.
- 최종 답변: 핵심 개선과 결과물 경로, 네 스킬 적용/제외 이유, 검증 결과·제한, Council 프로세스 상태 / 근거 신뢰도 / 미해결 주장, 실제 Creative 제안과 채택·보류·거절 이유. 자세한 역할·시도 기록은 작업 폴더에 보존한다. 리뷰 전용이면 제안만 전달한 범위를 밝힌다.

## 호출 예시

- `$total로 이 프로젝트의 구조·UI·사용성을 검토하고 개선해줘.`
- `$total C:/path/to/project — 핵심 기능을 유지하면서 개선하고 실행 확인해줘.`
- `$total로 이 포트폴리오를 개선해줘. 기존 경험의 사실은 유지해줘.`
- `$total로 이 프로젝트 검토만 해줘. 수정하지 마.`
