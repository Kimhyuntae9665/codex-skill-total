# Council 패킷과 적용 지점

Council의 모델·게이트·재시도·통합 계약은 원본 SKILL.md를 읽고 따른다. 이 참조는 total에 필요한 내용만 더하며 역할 수나 결과 형식을 바꾸지 않는다.

## 고정 패킷

원문 요청, 명확한 대상 경로, 목적·독자·사용자, 허용/제외 범위, 기준 화면·소스·기능, 실패 재현, 검증 명령·환경, 사실/추론/미확인을 분리한다. 포트폴리오는 공고·기존 경험·증거의 확인 상태와 최종 형식을 포함한다. 조사한 화면의 경로·날짜와 코드 파일/행을 남긴다. 파일명만으로 디자인 방향을 추정하지 않는다.

패킷을 원문 요청과 대조해 누락을 확인하고 고정한다. 적용 전에 새 근거를 확인하되 핵심 사실이 바뀐 결론을 동일 Council의 검증된 결론처럼 말하지 않는다. 경미한 변화는 이유를 기록하고, 방향을 바꾸는 변화는 영향을 받는 결정을 조건부/보류로 남기거나 필요한 경우 별도 Council을 실행한다.

모든 역할에 같은 패킷을 제공하고 네 도구의 실제 적용 지점을 평가하게 한다. 도구별 별도 보고서나 결과 수를 advisor에게 강제하지 않는다.

| 역할 | total에서 추가할 관점 |
|---|---|
| Strategist | 목표 작업·독자가 확인해야 하는 가치, 고칠 순서·기회비용 |
| Skeptic | 사실·변경 영향·회귀·근거 없는 지표·적용 조건 |
| Creative | 설명/화면의 가정을 바꿀 유용한 대안, 작고 되돌릴 수 있는 검증 |
| Operator | 파일·의존 관계·담당 도구·실행 순서·검증·복구 범위 |
| Audience Advocate | 첫 화면 이해·조작·가독성·신뢰·읽는 흐름 |

투표 대신 근거와 목적에 따라 적용을 선택한다. 실행 프로필은 런타임 노출 정보로 확인한다. 모델·tier 실제 사용을 자기 보고만으로 확정하지 않는다. 시도별 시작/종료·terminal·재시도·확인 불가 사용량을 원본 Council대로 기록한다.

## 적용 지도

루트가 아래 수준으로 정리한다. advisor의 출력 형식을 대체하는 표나 고정 quota가 아니다.

| 스킬 | 상태 | 지점과 근거 | 변경/산출물 | 완료 관찰 |
|---|---|---|---|---|
| Graphify | 적용/해당 없음/근거 부족/실행 불가 | 현재 소스·변경 관계 | 분석·영향 범위 | 소스 대조 및 별도 핵심 기능 테스트 |
| UI/UX Pro Max | 같은 네 상태 중 하나 | 실제 정보·조작 문제 | 디자인 기준·화면 | 작업 이해·조작·가독성 확인 |
| Impeccable | 같은 네 상태 중 하나 | 화면·재현 가능한 사용성 문제 | 구현·마감 | 실제 화면·상태 확인 |
| Archify | 같은 네 상태 중 하나 | 설명이 필요한 실제 구조·흐름 | 대화형 HTML | finalize 결과·실제 관찰 범위 |

`해당 없음`은 근거를 확인해 관련 없다고 판단한 상태다. 입력을 아직 못 봤다면 `근거 부족`, 필수 실행 방법·허용된 대체 경로가 모두 실패했다면 `실행 불가`다. 코드 없는 PDF도 문서 관계 분석이 필요한지 확인하되 semantic backend 부재를 임의 외부 API 호출로 해결하지 않는다.

Council 실패는 개선 적용 전에 멈춘다. 개별 경로 실패는 해당 개선에 영향을 주며, 독립적인 개선은 권한 안에서 진행할 수 있다. 누락된 필수 개선은 완료의 제한으로 명시한다.
