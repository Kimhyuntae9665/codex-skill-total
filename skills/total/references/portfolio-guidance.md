# Portable project and portfolio guidance

Use the target repository's AGENTS.md and the user's current request first. This public bundle does not depend on the original author's private career records or local guidance folder.

For new projects or full portfolio reconstruction, consider an executable simulation of the actual target work: input → rules/constraints → state changes → observable results. Implement and inspect it when it fits the authorized scope; respect requests for documents only, existing material only, or no new implementation. Decorative motion and invented metrics do not establish a working simulation.

For career materials, use the supplied official job description and verified candidate evidence. Connect each emphasized case to the actual target task. An existing project can be described as applicable to that task; do not rewrite its original motivation or imply deployment at the company. Separate individual/team contribution, proposed/implemented work, synthetic/measured data, and demo/production outcomes.

When the user has not specified a portfolio length, a concise three-page PDF including the cover is a starting recommendation, not a requirement overriding the user's format. Give each page a large relevant artifact and readable explanation. Screenshots need continuous visible borders outside all four edges and separate captions. For simulation screenshots/diagrams, use brief observation guides and numbered connectors to actual elements without covering controls or values. Keep the original capture intact.

Render the final format and inspect whole-page and 100% views for text, image boundaries, caption/callout alignment, truthful task connections and page constraints. For interactive projects also exercise changed inputs, calculations, reset, empty/error states and the core user task. Keep proposed additions distinct from existing verified experience. Sending applications or publishing/deploying artifacts requires the user's applicable authorization.
